# OctoAcme — Project Status Reporting

## Purpose
Define a reusable project status reporting skill that turns delivery evidence into stakeholder-ready updates.

## Scope
Use this guidance for weekly, sprint-end, and milestone stakeholder updates across active projects.

## Evidence Gathering Expectations
- Use verifiable inputs from delivery systems (project board movement, merged PRs, test/quality signals, release notes, incident trends, and risk register changes).
- Link evidence to each claim in the report so stakeholders can drill into details.
- Distinguish completed outcomes from in-progress work and planned next steps.
- Validate dates, owners, and dependency status before drafting the report.

## Standard Report Format
Use this structure for each update:
- Reporting period:
- Overall status (Green / Amber / Red):
- Outcomes delivered:
- Evidence links:
- Milestones due next period:
- Risks and blockers:
- Decisions or support needed:
- Escalations opened (if any):
- Owner and next update date:

## Green / Amber / Red Criteria
- **Green:** Milestones are on track, no material blockers, and risks are controlled with active owners.
- **Amber:** Delivery risk is increasing (scope, schedule, quality, dependency, or capacity), but recovery is still feasible within the current plan window.
- **Red:** Critical milestone miss or severe blocker with no near-term recovery path without leadership intervention or plan reset.

## Escalation Guidance
- **Amber status:** notify PM and Product Lead in the same reporting cycle, include mitigation plan and explicit owner.
- **Red status:** escalate to sponsor immediately, document impact, options, and decision deadline.
- Escalate any unresolved cross-team dependency that threatens committed milestones.

## Pre-share Checklist
- [ ] Status color matches current evidence and milestone forecast.
- [ ] Outcomes and metrics are backed by links to source evidence.
- [ ] Top risks include owner, mitigation, and expected resolution date.
- [ ] Required decisions/support requests are explicit and assigned.
- [ ] Escalations were routed according to severity and timeline.
- [ ] PM and Product Lead have reviewed the update before sharing.
